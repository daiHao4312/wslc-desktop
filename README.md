# wslc-desktop

**中文** | [English](README.en.md)

为 WSL 容器（[`wslc`](https://learn.microsoft.com/windows/wsl/)）打造的原生 Windows 桌面管理面板。
WinUI 3 + .NET 10，**非打包 + 自包含单文件**分发：目标机无需安装 .NET 运行时，也无需 Windows App SDK 运行时。

## 功能

| 模块 | 内容 |
| --- | --- |
| 容器 | 列表 + 实时 CPU/内存、启动/停止/重启/强杀/删除（全部二次确认）、批量操作、端口一键打开、详情浮层（inspect / **日志快照 + 内嵌实时跟随 + 另存为文件** / **可停止的命令执行**（实时输出，停止作用于容器内进程）） |
| 镜像 | **拉取对话框**（镜像源 / 仓库 / tag 分段填写，镜像源候选 = 内置加速站与 Docker Hub 官方源 **+ 你自己添加的源**、10 个常用镜像快捷入口，**一键列 tag** 并按"latest 优先 → 版本倒序"排序，选中 tag 自动量下载体积）、**私有仓库认证**（凭据在设置里配一次，拉取/列 tag 时按镜像源自动使用）、**重命名 / 改标签**、**导出为 tar 归档 / 从 tar 导入**（一个归档可装多个镜像，批量条可多选一次导出）、本地表、拉取（实时进度、可取消）、删除、一键用该镜像创建容器 |
| 网络 / 数据卷 / 会话 | 列表与增删（内置网络禁删、删除前写明连带后果） |
| WSL 发行版 | `wsl -l -v` + 注册表 Lxss：状态/版本/默认/安装位置/VHDX 占用、启动/终止/设默认/终端进入/注销 |
| 添加发行版 | 本地安装包导入（`.tar`/`.tar.gz`/`.tar.xz`/`.vhdx`/`.wsl` 按后缀自动选装法）或从微软清单**在线安装**（`wsl --list --online`）；带**装前检查**（重名/目录/后缀）与**实时等效命令预览**，安装过程流式显示可取消 |
| 发行版详情 | 压缩磁盘（回收已释放块）、开关稀疏盘、调整磁盘大小、**移动安装位置**、**导出为 tar 归档**（显示已写入字节数、可取消）、编辑 `/etc/wsl.conf`（保存前自动备份）、设置默认用户、打开安装位置 |
| 创建容器 | 完整表单 + **实时等效命令预览**（与真正执行共用同一份拼装逻辑），可从镜像 inspect 预填端口与启动命令；支持 **GPU 直通（`--gpus all`）**、主机名/域名、内存与 CPU 限制（内存单位自动规范成大写） |
| 设置 | 面板偏好、**镜像源管理**（一张列表管内置与自定义：单选定默认、勾选「显示」决定是否进下拉、编辑改备注/凭据、删除自定义源，带搜索与滚动）、`settings.yaml` **表单 ↔ 原始 YAML 双模**（逐行替换以保留注释、保存前自动时间戳备份） |
| 事件流 | `wslc events` 长驻订阅驱动即时刷新（断线重连 + 续接去重），轮询降级为兜底 |
| 桌面集成 | 托盘常驻、关闭到托盘、单实例、快捷键 `F5` / `Ctrl+R` / `Ctrl+N` / `Ctrl+1–8`、Mica 与深浅色即时切换 |
| 关于页 | 环境自检（引擎/内核/组件缺失）+ **一键安装/修复引擎组件**（带进度，装完复查）+ **导出诊断包**（版本 / 引擎 / 会话 / API 通道状态 + 脱敏偏好 + 日志末尾）+ 基于 GitHub Releases 的更新检查与**在线更新**（下载 → sha256 校验 → 原地替换 → 自动重启，旧版本留 `.old` 备份） |

## 环境要求

- Windows 10 1809+ / Windows 11
- WSL 容器引擎 **3.0.1 及以上**（`wsl --update`）。版本不足或组件缺失时面板会给出可操作的升级提示
- 构建需要 **.NET 10 SDK**；**运行发布版不需要任何运行时**（自包含）

## 构建与运行

双击或命令行执行仓库根目录的脚本：

```bat
启动.bat            :: 直接启动现有构建产物
启动.bat build      :: 先构建再启动
跑测试.bat          :: 全量测试（含 Live 实机联调）
跑测试.bat unit     :: 跳过 Live 实机联调，更快
```

手动命令：

```bat
dotnet build WslcDesktop.slnx -t:Rebuild
dotnet test  tests\WslcDesktop.Core.Tests\WslcDesktop.Core.Tests.csproj
```

> `启动.bat` / `跑测试.bat` 必须保持 **GBK(ANSI) 编码 + CRLF 换行**：cmd 按代码页 936 解析批处理，
> 存成 UTF-8 会让中文变乱码字节、甚至拆散注释行导致后续语句被当命令执行。`.gitattributes`
> 已经把这两个文件钉死在 CRLF，编码仍需编辑器里显式选择。

> **不要用 `dotnet run`**：本项目是非打包 WinUI 3 应用，`Microsoft.Windows.SDK.BuildTools.WinApp`
> 的 Run 钩子会按"打包应用"启动，未开启开发者模式时直接报
> `Failed to launch application: Developer Mode is not enabled`。请构建后直接运行 exe。

## 目录结构

```
src/WslcDesktop.Core/      服务层：wslc CLI 通道、模型、解析器（纯函数 + fixtures 单测）
src/WslcDesktop.App/       WinUI 3 界面：10 个页面、详情浮层、托盘、单实例
tests/WslcDesktop.Core.Tests/   xUnit：解析/拼命令/事件流/偏好/更新检查 + Live 实机联调
```

## 命名约定

应用名统一取仓库名 **`wslc-desktop`**，不存在第二个写法：

| 位置 | 值 |
| --- | --- |
| 仓库 / Release / 发布 exe | `wslc-desktop`、`wslc-desktop.exe` |
| 窗口标题 / 托盘提示 / 关于页 / 应用属性 | `wslc-desktop` |
| 程序集名（`AssemblyName`） | `wslc-desktop` |
| C# 命名空间 | `WslcDesktop`（App）、`WslcDesktop.Core`（Core / Tests） |
| 项目与目录 | `WslcDesktop.App` / `WslcDesktop.Core` / `WslcDesktop.Core.Tests` |
| 数据目录 | `%LOCALAPPDATA%\WslcDesktop\`（`prefs.json`、`error.log`） |

> 命名空间根用 `WslcDesktop`（而非 `WslcDesktop.App`）是刻意的：App 页的类是 `WslcDesktop.App`，
> 若命名空间尾段也叫 `App`，`WslcDesktop.App.App` 会让「命名空间 / 类型同名」在解析时产生歧义。
> 带连字符的小写 `wslc-desktop` 只用于**外部标识**（文件名、标题、UA），不进入 C# 标识符。

## 测试基线

- 单元测试 + `Live*` 实机联调必须全绿（`Live*` 在引擎不可用时自行跳过，不会让套件变红）
- 渲染 / 布局 / 真实交互必须本机实测：CI 查不出这类问题

## 已知边界

- 官方 `wslc compose` 尚未发布，本面板不自研编排层
- **日志跟随已在面板内**（快照 + 实时跟随 + 另存为文本）。交互式程序（`vi` / `top` 这类需要 TTY 的）仍交给
  Windows Terminal（`wt`），不可用时退回控制台窗口 —— 官方 API 只暴露字节流、没有 PTY，自建终端不在本面板范围内
- **在线更新**是"确认后才下载、确认后才替换"的手动流程，不做后台静默自动更新；每次更新需全量下载约 96 MB（GitHub 不提供增量差分）
- 在线更新要求程序所在目录**可写**：装在 `C:\Program Files\` 等受保护位置时会提前识别并引导改用「打开下载页」手动替换，不会先下 96 MB 再失败
- 更新包未做代码签名，靠 GitHub 发布资产的 **sha256 摘要**校验完整性；由于是程序自己发起下载（不带浏览器的 Mark-of-the-Web），不会触发 SmartScreen 拦截
- **拉取进度默认走 CLI（不确定态）**，官方 C# API 通道只在能附着到引擎会话时才给出真实字节数。
  实测约束：官方 API 的会话名是**机器级唯一**且由创建它的进程独占（CLI 的容器都在 `wslc-cli-<用户>` 会话里，
  归 `wslc.exe` 所有），所以面板**只能做只读附着**，拿不到时自动回落 CLI。
  「设置 → 官方 API 通道」下方会显示**当前的真实状态**（可用 / 只读附着 / 不可用原因）——
  宁可告诉你"现在是 CLI"，也不假装有 API 加速
- **私有仓库凭据在「设置 → 私有仓库凭据」里配一次**，之后按镜像源自动使用：密码用 **Windows DPAPI（当前用户）加密**后
  存进本机 `prefs.json`，明文不落盘、不写日志；换台机器或换个 Windows 账户读出来就是一串解不开的 Base64。
  设置里可以点「测试」当场换一次令牌，把"密码对不对"问清楚，不用等到拉取失败。公开镜像完全不需要配置。
- **「设置 → 镜像源」是一张统一的列表**：内置站点（含默认的那个）与你添加的源一模一样，字段也一模一样
  （备注、凭据状态、是否启用）。操作只有一套 —— 行首**单选**决定默认源，行尾**「显示」勾选**决定它是否进下拉，
  **「编辑」**改备注与凭据，**「删除」**只对自定义源出现。顶部有搜索框，源多了按主机名/备注/用户名过滤。
  私有源的密码用 Windows DPAPI 加密后存本机；保存凭据时会顺手换一次令牌，密码不对当场告诉你。
- 镜像 tag 列表直接问 registry 拿（官方 API 与 `wslc` 都不提供）。默认镜像源是 **`docker.1panel.live`**（实测 tag 与 manifest 都免认证、**免代理可用**）；**Docker Hub 官方源（`registry-1.docker.io`）也在可选列表里**，公开镜像靠匿名令牌即可列 tag，但它需要能连通外网 —— 国内直连常超时，可开代理。其余站点（`docker.1ms.run` / `docker.m.daocloud.io`）需要各自域名下的令牌，可以手填 tag 直接拉，界面会提前说清而不是让你等一次注定失败的请求。**你填的镜像源不会被改名**——写 `docker.io` 就一直显示并用 `docker.io` 拉取，只有在查询 tag 时才在内部连真正的 API 端点 `registry-1.docker.io`
- **镜像导出 / 导入**走 `wslc save` / `wslc load`：引擎导出时**不输出任何进度**，所以导出只有"已写入 N MB"而没有百分比；
  导出失败或取消会**删掉写了一半的 tar**（半截文件拿去导入只会得到更含糊的错误）。归档格式只保证与本面板
  和 `wslc load` 互通，与 `docker load` 的交叉兼容未做验证
